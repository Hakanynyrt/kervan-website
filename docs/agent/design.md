## Design system

`packages/ui/src/tokens.css` is the single source of truth. Use Tailwind token utilities / CSS variables; never hardcode hex values in components.

- **Contrast:** every text token must stay >= 4.5:1 on `bg`, `bg-soft` and `bg-warm` (`ink-soft` is `#918879` for that reason; check with the WCAG formula before changing it). Form fields use `border-ink-soft` (UI boundaries need 3:1). The WhatsApp button uses `bg-whatsapp` (`#128c7e`, white glyph 4.1:1), not the bright brand green; the shop, whose WhatsApp buttons carry 14 px text, overrides it to `#0f7a6e` (white 5.21:1) in its `globals.css`.
- **Palette ("Mood C", dark):** `bg #0A0A0B`, `bg-soft #141416`, `bg-warm #1C1C20`; `ink #E8E2D6`, `ink-mid #B8AFA0`, `ink-soft #7A7066`; brand "Forge Ember" `#E8431B` (`brand-hi #FF5C32`, `brand-lo #C53614`).
- **Day theme (kervanbreaker.com, kervanheat.com):** light by day, Mood C at night, by the visitor's sun (the same edge middleware as the shop, see `platform.md` "Day / night by the sun"). Day tokens are redefined in each app's `globals.css` under `:root[data-theme='light']` and `:root[data-sun='day']:not([data-theme='dark'])`; no mark ⇒ Mood C (dark-first). Breaker "paper": `bg #F6F3EE`, `bg-soft #EEEAE3`, `bg-warm #E6E0D6`, `ink #1A1714`, `ink-mid #4A433A`, `ink-soft #665D52`, `brand #B0350E` (hover `#962D0B`); kervanheat.com (2026-10-28 redesign) is a cool white day and a graphite night instead: `bg #FFFFFF`, `bg-soft #F5F6F7`, `panel #FFFFFF`, `hair #E2E5E8`, `ink #15171A`, `ink-mid`/`ink-soft #646B74`, `brand #C23A16` with white labels; night `bg #1A1D20`, `bg-soft #202427`, `panel #24282C`, `ink #ECEAE6`, `ink-mid #A5A9AD`, `brand #F26A45` with a dark label `on-brand #16110E` (all tokens and ratios in `heat-treatment.md`). Same rules: every text token >= 4.5:1 on all three backgrounds (lowest: breaker ink-soft 4.92, brand 4.76; heat ink-mid and brand 4.96 on bg-soft), page colour on breaker's brand buttons 5.6:1. Heat sets its night palette unlayered on `:root` in its `globals.css` (the day block still wins by day), uses no `SectionHeading` and no eyebrows, and its fields are bordered with `field-line` (≥ 3:1). Heat no longer has a `.kv-night` band (its 3D opening was replaced by a photo hero; the 3D gear section `GearProcess` is its own themed block that follows the page theme, so the Nav assumes no dark band, and it keeps the "no AI look" rule: warm light only on the gear's surface, no glow or gradient, brand-token button); breaker's home is light all the way by day, its 3D tip relit for a light studio (`breaker-parts.md`). Brand buttons are `<a>`s whose `text-bg` loses to breaker's global unlayered `a { color: inherit }`, so its `globals.css` sets their colour explicitly; heat keeps that reset in `@layer base`, so utilities win, and its brand buttons use `text-on-brand`. Header theme select: `ThemeSelect` in `@kervan/ui` (`kv_theme`, lg+), copy in each dict's `nav.theme`.
- **Type:** display Fraunces (`--font-serif`), body/UI Inter (`--font-sans`); kervanheat.com uses Inter only since 2026-10-28 (no Fraunces files or `@font-face` there). All three sites serve them themselves (2026-10-28, Lighthouse: the third-party font stylesheet held back the first paint on phones): `public/fonts/inter-latin(-ext)-v20.woff2` (variable 400–700) and, on kervanbreaker, `fraunces(-italic)-latin(-ext)-v38.woff2` (variable 300–700 with the opsz axis), latin + a trimmed latin-ext (`*-latin-ext-a-*`: Latin Extended-A U+0100–017F, which holds Ğ ğ İ Ş ş, plus ș ț and the currency signs; cut from Google's latin-ext with fontTools `pyftsubset`, Inter 85 → 20 KB; a character outside it falls back to the system font), `@font-face` in each app's `globals.css`, the Inter latin file preloaded, `/fonts/*` immutable. A Google Fonts request for Fraunces must include the italic axis (`ital,opsz,wght@0,…;1,…`), otherwise the browser fakes the italics the headings rely on; the unused `SOFT` axis is not requested.
- **Radius:** 6 / 14 (cards) / 20 (large surfaces) / 999px (pills, buttons). kervanheat.com: 2 px buttons and fields, 4 px frames and cards, no pills.

## Motion

- One ease: `--ease-editorial` = `cubic-bezier(0.22, 1, 0.36, 1)` (`editorialEase` in `@kervan/motion`). Prefer the shared variants over ad-hoc ones.
- Durations: micro 150ms, small 250ms, medium 400ms, large 600ms. Nothing longer than 600ms unless it is a deliberate hero moment. Stagger children 60–80ms.
- In-view reveals animate once (`{ once: true, amount: 0.3 }`); no more than 3 simultaneous animations on screen.
- **`useReducedMotion` is mandatory** in every animated component — short-circuit to the static state. Import it only from `@kervan/motion`, never from `framer-motion`. `globals.css` also has a `prefers-reduced-motion` floor.
- Static vs animated mode: the prerendered HTML is the final static state (no visible intro curtain: heat's curtain markup is `display:none` without `kv-intro`; no 3D canvas). An inline `<head>` script adds `js-anim` to `<html>` only for JS-running humans without reduced motion (bots/headless/webdriver excluded). With `js-anim`, `main.tsx` does `createRoot` (today's animated site; on breaker-parts `#root[data-prerendered]` is hidden until the first render, at most 4 s; kervanheat.com never hides it: see Intro); otherwise it `hydrateRoot`s in static mode (`StaticMotionProvider`, where `useReducedMotion()` is true) and must match the server markup exactly. Heavy effects (the 3D scene) mount client-side only: three.js is reached only through a dynamic `import()` after idle and near the viewport, never in the prerender, and reduced motion, Save-Data or a WebGL failure show the static poster instead (heat's `GearProcess` is the pattern).
- Intro: kervanheat.com's curtain is pure CSS in the prerendered HTML (`.kv-curtain*` markup and the inline `<style>` in `scripts/prerender.mjs`; the former `IntroOverlay` component is gone, 2026-10-28). The head script adds `kv-intro` to `<html>` for animated visitors whose `sessionStorage` lacks `INTRO_SESSION_KEY` (`src/lib/intro.ts`) and sets the key, so it plays on the first page of a visit only (owner, 2026-10-28). It starts with the first paint, not after the script: two `--color-bg` halves part after 0.4 s, a brand hairline in the middle, the name (Inter bold) fades in and out, the page scroll is locked until 2.4 s and the curtain is gone at 2.8 s; the page under it is already painted (Lighthouse: no blank wait for the script). Breaker-parts has no intro. Hero sequences must account for it (delay until it finishes, or skip the delay when the session flag is set).

## Accessibility

- WCAG AA contrast: 4.5:1 body text, 3:1 large text and non-text UI.
- Focus ring: `2px solid` brand with `outline-offset: 2px` (`focus-visible:outline focus-visible:outline-2 focus-visible:outline-brand focus-visible:outline-offset-2`). Restyle focus rings, never remove them.
- Tap targets (kiriciparca.com, 2026-10-27): below `lg`, WhatsApp, phone and order links and the header quote button are at least 44 px high (`min-h-11`), reached with padding, never with a larger font; an inline text link gets vertical padding (`max-lg:py-[14px]`), which enlarges its hit area without moving the line.
- Every interactive element (buttons, links, form fields, carousel/gallery controls, language toggle, menu) must be keyboard-reachable and Enter/Space-activatable.
