## breaker-parts (kervanbreaker.com)

- React Router app: `src/pages/` (Home, Products, ProductDetail, Brands, Production, About, Contact, NotFound); sections in `src/components/` and `src/sections/`; product/brand data in `src/data/`.
- Product pictures: `image` in `src/data/products.ts` (empty = the placeholder), optional `imageSrcSet` (used with `sizes` by `ProductGrid` and `ProductDetail`) and `ogImage` (1200×630 link preview, else `image`). Tie rod, alt gövde, kama, saplama and yan saplama use studio renders of the shop's own GLBs (`public/photos/parcalar/<slug>-{1024,1536}-vN.webp`, `og-<slug>-vN.jpg` with a small "Görseller temsilidir · Images are illustrative" note, 2026-10-23); their products carry `illustrative: true`, which captions the picture with `productDetail.illustrativeNote` (TR "Görseller temsilidir", EN "Images are illustrative") under the image on `ProductDetail` and as a small tag on the `ProductGrid` card. Real photos (keski, piston, burç, tamir kiti) have no caption. Saplama shows a tie-rod set (rod, nuts, washer); its text was changed to the shop's saplama group (tie rods and side bolts), owner's decision 2026-10-23.
- `public/_redirects` has **no** SPA fallback: every route is a prerendered file, unknown paths get `404.html` with HTTP 404. Heat-treatment URLs are 301'd to `https://kervanheat.com/`.
- Photo weight (2026-10-28, Lighthouse): product and workshop photos referenced in `src` are `-w1280.webp` copies (1280 px wide, WebP q78) of the original JPEGs, which stay in `public/` but are no longer linked; a new photo gets the same treatment. The workshop carousel (`StackedCarousel`) sets a card's background picture or video poster only while the card is in the visible rack (two either side of the active one), so the page no longer loads every card's photo up front. The product cards (`Products`) use a lazy `<img>` instead of a background picture. Fonts are self-hosted (see `design.md`).
- Home first screen: `src/components/Hero.tsx` + the `.kv-hero` block at the end of `globals.css`, copy in the dict's `hero` block (TR+EN, including the photo alt and caption). Left: H1 "Kırıcıyı ayakta tutan parçalar.", one sentence, two buttons (`#contact` primary, `#products`), three facts (2004 / Kartepe / 40+ kırıcı markasıyla uyumlu; every claim already exists elsewhere in the dict: the 40+ is the same as the meta description's); right: one workshop photo with a single hairline frame and a 14 px caption. Below 1024 px the order is copy → primary button → photo → facts, so the button is on the first phone screen (390x844). On desktop the photo fills the hero height and the facts sit on its bottom line. The photo is cropped from the original `public/photos/uclar/uclar-pile.jpeg` (1536x2048) into `uclar-pile-hero-{1024,1536}-v1.webp` (square, desktop) and `uclar-pile-hero-mobil-{768,1536}-v1.webp` (4:3, phone), WebP quality 82, served through `<picture>`/`srcSet`; the 1536 px files are the original's full width (no upscaling), so a changed crop gets a new name (`-v2`). Motion: one CSS push-in (scale 1 → 1.04, 24 s, `forwards`, no loop); `prefers-reduced-motion` turns it off. No scroll hijack, intro curtain or JS in the hero, so the prerendered HTML and the hydrated page are identical. The old 3D "Tek Parça" scene, `OpeningHold`, `IntroOverlay` and `kirici-ucu-siyah-02.glb` are gone (2026-10); `three` stays only for `ExportsGlobe`.
- Links to the shop kiriciparca.com (`src/lib/shop.ts`: `shopUrl`, `SHOP_PATH` product slug → shop page; `components/ShopLink.tsx`; copy in the dict's `shop` block): a "Mağaza ↗" menu entry (desktop from `lg`, and the mobile menu), a line under the quote button on product pages (`saplama` links the shop's saplama group), one line under the products grid, the compatibility page and the 404, a link under each make on the compatibility page to that make's shop page (`SHOP_MAKE_PATH` in `src/lib/shop-paths.ts`, `/marka/<slugify(make)>`, anchor `shop.makeLink` + the domain, e.g. "Rammer kırıcı modelleri — kiriciparca.com"; only makes the shop lists: Epiroc and Kobelco have no shop page and no link; `src/lib/shop.test.ts`, run by `pnpm test`, checks every path against the shop's slug rule and every product path against the shop's groups), an "Online mağaza" row on the contact page and the footer, which also links kervanheat.com. The footer's bottom legal row also carries a small, low-emphasis link to `/teknik-bilgiler` (label `nav.tech`; a plain `<Link>`, no tooltip; it replaced the removed 3D scene's hidden star). The footer's social icons come from `ORG_SOCIALS` (`@kervan/seo`, labels in the dict's `footer.social`) and every public email shown is `ORG_PUBLIC_EMAIL`; never hard-code either. Sister-site links open in the same tab with no `rel`, like `SisterSiteStrip`, and never promise prices (only the owner's priced parts show one). The global `a { color: inherit; text-decoration: none }` rule in `globals.css` (both apps) is unlayered and outranks Tailwind's colour/underline utilities on an `<a>`, so style a link's text on an inner `<span>`.
- Day theme: the whole page is the paper day palette by day and Mood C at night (owner 2026-10-13); the hero uses the theme tokens only (`--color-bg`, `--color-ink`, `--color-brand`, …), so the Tema select or a `data-sun` change restyles it with no JS. - Its Pages Functions are the owner-only `api/tech/*` endpoints (see "Owner-only Teknik Bilgiler") and `functions/_middleware.ts`, the day/night mark for pages (see `platform.md`; it passes `/api/*` and every non-HTML answer through untouched). ## Private VEGA tip catalog (breaker-parts, KV)

- The owner-only tip catalog (609 rows, ~420 KB) is **not** in the repo or the bundle and is too big for a Pages secret (5 KB limit). It lives in a Workers KV namespace bound to the `kervan-breaker-parts` Pages project as **`VEGA_CATALOG`** (Production only), key `catalog:v1`.
- `GET /api/tech/catalog` (`functions/api/tech/catalog.ts`) returns it only for a valid owner session (same host + cookie checks as `/api/tech/content`). No session → JSON 401 before KV is read; no binding → 503; empty key → 404. `smoke.sh` checks the anonymous 401 only.
- Update the data without a deploy: `node scripts/vega-import.mjs <catalog.csv> <out.json>` (writes **outside** the repo, refuses paths inside it), then upload `out.json` to KV key `catalog:v1` (dashboard: KV → namespace → Add entry → Upload file). Never commit the CSV or JSON (`*.csv` and `vega-catalog*.json` are gitignored). Keep the namespace unbound in Preview.
- Optional KV key `popular:v1` in the same namespace: `{ schema: 1, models: { "<catalog model>": 1 | 2 }, aliases?: { "<breaker name>": "<catalog model>" } }` (1 = sells most in Turkey, 2 = sells well). The endpoint returns it next to the catalog; missing/malformed ⇒ no badges, catalog unaffected. It is business data: never commit it — the owner pastes it in the dashboard (KV → namespace → `popular:v1`).
- Technical drawings (the side-view drawing with dimensions under each model in the VEGA PDF) live in the same namespace as one value, key `drawings:v1` (~2.4 MB). Build it with `node scripts/vega-drawings.mjs <catalogue.pdf> <catalog.json> <out.json>` (needs `pdftohtml` + ImageMagick `convert`; writes **outside** the repo; exits non-zero if any row has no drawing). The PDF stores the images out of order, so the script pairs them by position and part numbers, never by file order. `GET /api/tech/drawings` serves it under the same session rules as the catalog (401 before KV, 503 without the binding, 404 when empty); the page fetches it once when the first detail panel opens and shows nothing when it is missing. `smoke.sh` checks the anonymous 401 only. Never commit the PDF, images or JSON.
- Drawing-derived features: each catalog row may carry `rearStep` (boolean: the rear end is a narrower stub with a shoulder), `slotEnd` (`'rounded' | 'tapered'`: the key slot ends in a short radius or a long conical ramp) and `tipAngleDeg` (the number printed on the tip view, e.g. 45). They are read from the drawings (two independent vision passes plus a tie-break pass; `rearStep` is cross-checked against the table's rear diameter, `tipAngleDeg` against the catalogue text) and merged with `node scripts/vega-attrs.mjs <catalog.json> <attrs.json> <out.json>` (outside the repo; the result replaces `catalog:v1`). Missing/`null` means unknown, and the catalog tab never hides a tip over an unknown value. The slope of the rear shoulder is **not** offered: the drawings are too small to tell a chamfered shoulder from a square one (the passes agreed on only 71 % of rows).
- Owner-only reading guide: optional KV key `guide:v1` (`{ schema: 1, breakage: { intro, zones[], defectVsMisuse, claimChecklist, disclaimer } }`, TR+EN) is returned as `guide` by `/api/tech/catalog` and shown as a collapsible panel "where a tip breaks / what warranty covers" in the catalog tab. It is industry-norm research, not Kervan's own terms; Kervan's warranty terms are the owner's decision and, if added, belong in this KV key, never in the repo. Missing/malformed ⇒ no panel, catalog unaffected.
- Usage guide and carrier weight (public, generic knowledge, in the repo): `lib/vega-usage.ts` maps the tip diameter to a rough carrier tonnage band (union of manufacturer/dealer data points listed in the file; none below Ø75 or above Ø209) and the dict holds a per-tip-type guide (rock, where, watch-out). Both are labelled as approximate; the breaker maker's own tip recommendation wins.
- Local test: `wrangler kv key put --namespace-id=VEGA_CATALOG --local "catalog:v1" --path <catalog.json>`, then `wrangler pages dev dist --kv VEGA_CATALOG --compatibility-date=2026-04-17` with test secrets in `.dev.vars`.

## Owner-only shared tips ("Ortak uçlar", shop D1)

- Which breakers take the same tip is shown in the third tab of `/teknik-bilgiler`, **Ortak Uçlar** (`#ortak-uclar`; `src/pages/tech/FitsTab.tsx`, a `React.lazy` chunk; copy in the dict's `fitsUi`, TR+EN). Two views: _Kırıcıdan_ (search-as-you-type over make + model with the shop's `matches` / `rewriteQuery` from `@kervan/tips`, so spacing, dashes, Turkish letters, other catalogue spellings, `SAME_MODELS` and misspelt makes all find it; Enter takes the first hit) shows the breaker's tip families (Ø, code, collar Ø, key count, key section, slot length, rear step, tip types) and, per family, every other breaker on the same tip grouped by make with counts (own make first, long makes folded behind "Tümünü göster"); _Uç ölçüsünden_ lists every working diameter with its breaker count (a typed number narrows them, a typed code such as `KU135-21` lists matching families) and shows each family's breakers. Every breaker is a button that jumps to it; each pick is a history entry (`#ortak-uclar/k/<slug>`, `#ortak-uclar/d/<Ø>`), so the phone's back button walks back. No prices, lengths or weights.
- Data: `GET /api/tech/fits` (`functions/api/tech/fits.ts`), same session/host/cookie rules as `/api/tech/catalog` (no session → JSON 401 before any data is read; no binding → 503; no rows → 404). It reads the shop's D1 database `kervan-shop` through the Pages binding **`SHOP_DB`** (Production only, like `VEGA_CATALOG`) with the same queries as the shop's build (`packages/tips/src/catalog-sql.ts`, imported as `@kervan/tips/catalog-sql`; prices and stock are not selected), applies Kervan's drawings (`applyDrawings`) and `toPublicCatalog` (published rows only, `WRONG_FITS` and hidden makes left out), then `buildFitsIndex` (`packages/tips/src/fits-index.ts`, unit-tested with invented rows) groups the breakers the way the shop groups its breaker pages. The answer is cached in the isolate for 5 minutes, so a price-sheet or data import shows up within minutes with no deploy. The function only runs `SELECT`s; never write to D1 from kervanbreaker.com. The client keeps the data in memory only and drops it on sign-out.
- Setup (owner, once): Cloudflare → Workers & Pages → `kervan-breaker-parts` → Settings → Bindings → Add → D1 database, variable name `SHOP_DB`, database `kervan-shop`, **Production** only, then redeploy (Actions → Deploy → Run workflow → `breaker-parts`). No new secret. Until then the tab says the list is not connected (503).
- Local test: seed a local D1 with `apps/parts-shop/migrations/0001_init.sql` + `0004_drawing_overrides.sql` and rows rebuilt from the shop snapshot `apps/parts-shop/.catalog/catalog.json` (a script outside the repo; no prices), using a throwaway `wrangler.toml` outside the repo with a `SHOP_DB` D1 entry and `wrangler d1 execute <name> --local --persist-to <dir> --file …`; then `wrangler pages dev dist --d1 SHOP_DB=<id> --persist-to <dir> --compatibility-date=2026-04-17` from `apps/breaker-parts` with test secrets in `.dev.vars`, and sign in on `http://localhost:<port>/teknik-bilgiler`.
