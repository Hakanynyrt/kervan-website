# iPhone app "Kervan Kırıcı Parça" (kiriciparca.com)

<!-- Read before working on the app (apps/parts-shop/src/app, the app build and its checks). Keep it current with each change. -->

## What it is

- An iPhone app for the shop kiriciparca.com: "Kervan Kırıcı Parça" (TR) / "Kervan Breaker Parts" (EN). Individual Apple account, no Mac, iPhone first.
- It is the shop's own React code built a second time: the app renders the shop's page components (`src/PageView.tsx`) inside its own shell. It reads every page from the live site at run time and carries no catalogue and no prices.
- No accounts, no sign-up, no server-side user data, no analytics, no ads. What it keeps (saved machines, language) stays on the phone.
- M1 is the app as a **web build** (`apps/parts-shop`, below). M2 (this stage) wraps the same build in a native iPhone project (`apps/parts-app`, Capacitor) and builds an **unsigned** `.ipa` on GitHub's macOS runner; the owner installs it with iLoader + SideStore and a free Apple ID. No Apple Developer membership yet, no signing, no secrets: TestFlight and the App Store come with the paid membership (M3, M6).

## How it works (M1)

- **Build:** `vite.app.config.ts`, entry `app.html` → `src/app/main.tsx`, output `apps/parts-shop/dist-app/` (gitignored): `index.html` (from `app.html`, Capacitor's start file, with a CSP that allows only the site origin and the picture host), the bundle and the two Inter fonts; no `public/` copy, no catalogue, no price file. `scripts/build-app.mjs` runs it with `VITE_APP=1` and `VITE_SITE_ORIGIN` (default `https://kiriciparca.com`; any other origin must be https, or http on localhost) and makes sure `index.html` and the fonts are there. Against the canonical origin the config sets `VITE_TIP_IMG_BASE=https://img.kiriciparca.com` unless it is given.
- **Shell:** `src/app/AppShell.tsx`: a top bar (back, title, "Makinelerime ekle" on breaker model pages; below 400 px wide the button shows its icon only, with the text as its `aria-label`, so the model's name keeps its room). The title is the page's own `main h1` (read when the page is parsed; the `<title>` only when there is none), the model's name on breaker pages, and on the app's own screens it is the screen's `h1` (shop pages bring their own `h1`, so there it is a plain line) and a tab bar Ana ekran / Rehber / Tara / Makinelerim / Palet (EN: Home / Guides / Scan / My machines / Cart; "Cart" is the owner's English word for the Palet, the Start shortcut and the tab's `aria-label` included). The site's `Layout`, header, footer, `ConsentBanner`, `ads.ts`, `page-head` and the sun middleware are not used. The shell provides `AstryxProvider` and `FinderPickProvider` as `Layout` does.
- **Data:** a route fetches `SITE_ORIGIN + localePath(path, lang)`, parses the HTML with `DOMParser` and `readPageProps()`, and renders `PageView`. Stale-while-revalidate cache in IndexedDB (at most 300 pages, with the fetch date). A page read in this session counts as today's for 10 minutes (`SESSION_TTL_MS`, as the palet's own re-read); after that, on going back online (which forgets the session's reads) or on coming back to the app, it shows as a saved copy while the site is asked again. The fresh copy re-renders the page in place (keyed by address only), so what was typed stays. An IndexedDB that does not answer within 1.5 s (`CACHE_WAIT_MS`) is given up for the session (memory only). A cached page not re-fetched in this session shows one dated line where the page shows prices ("Fiyatlar <tarih> tarihlidir; bağlantı olunca güncellenir."; `pageShowsPrices` in `src/app/prices.ts`: any filled price field in the props, so cards, priced renders and listed parts count too; `showsPrice` from `PageView.tsx` stays the site header's narrower "priced page"). The Palet's prices are its lines' own (stored when each was added): when it is not fresh and a line has a price, the line reads "Fiyatlar ürünün eklendiği günün fiyatıdır; bağlantı olunca güncellenir.", and the Cart page itself marks every priced line "Fiyat güncellenemedi" when no line's page could be read (site behaviour too). No network and no cache: the Offline screen, except `/palet`, which is built on the phone (`offlinePage` in `main.tsx`: the cart model with the exchange rate of the newest saved page). A picture that fails to load (offline) leaves an empty frame (`img[data-broken]`), not the broken-picture mark. An unknown page kind, or a page that throws: the UpdateNeeded screen with "Sitede aç" (error boundary).
- **Router:** History API on real paths, no library. A document-level click listener (and submit, for the two GET search forms) turns same-site links (relative, or absolute on the site origin) into `navigate()`; `wa.me`, `mailto:`, `tel:` and other hosts are left alone. Query strings (`?p=`, `?uc=`, `?tip=`, `?q=`, `?burc=`) and `#hash` keep working, because shop code reads `window.location` and calls `history.replaceState`. In-page `#anchor` links also go through `navigate()`: each jump is a history entry with the app's index (Back returns to where it started; the target takes the focus). An entry without the index is stamped on Back/Forward, and an entry from before a language change gets its address rewritten into the app's language.
- **Screens** (`src/app/screens`): Start (make/model search over the public `/kirici-modelleri.json`, shortcuts to `/kirici-ucu`, `/yedek-parca`, `/rehber`, `/palet`, the saved machines, language switch), Machines (saved `{path, name}` rows; each opens only its own `/kirici/<make>/<model>` page; parts lists of different models are never merged), Scan (M1: a placeholder and a field for a Kervan link; only https links on the site origin open, anything else gets "Bu bir Kervan bağlantısı değil"), Offline, UpdateNeeded. The Rehber and Palet tabs are the shop's own `/rehber` and `/palet` pages.
- **Device state:** `src/app/store.ts`, a small async key-value interface (web build and e2e: `localStorage`; inside the iPhone app: `@capacitor/preferences`, iOS `UserDefaults`, loaded on first use by `preferencesKV()`): machines and language. First run takes the language from `navigator.language` (`tr` → tr, else en).
- **Text:** every app string, `aria-label`s included, is in `src/app/dict.ts` (TR primary, EN secondary), never in components. The look is the shop's (tokens of `styles/globals.css`, Inter, `rounded-sm`; no gradients, glows, pill buttons, eyebrow kickers or serif italics); tap targets at least 44 px; safe-area insets on the top bar, the tab bar and the page's order bar (`data-sticky-bar`, bottom and sides); `prefers-reduced-motion` respected. The tab bar is glass (owner, 2026-11-15, the one exception to the flat look, app chrome only): a floating, rounded, translucent bar (`backdrop-filter` blur, hairline edge; solid with "Reduce transparency" or without blur support), the open tab a tinted bubble. On phones it floats over the bottom, 3.5 rem tall (`--kv-tab`), just above the home indicator (`--kv-tab-bottom`), and pages keep `--kv-tab-space` clear under them; labels never wrap (10 px below 400 px wide, 11 px above), checked by the e2e at 320 and 375 px in both languages. On a large screen (`width >= 640px and height >= 480px`: iPhone Duo's inner display, both ways round, never a phone in landscape) it is a rail on the right edge, centred top to bottom (`--kv-rail`), `--kv-rail-gap` from the screen edge whatever the right safe-area inset (on the Duo's inner display that inset is the status corner's width and left the rail a column away from the edge; owner, 2026-11-15), and pages and the order bar keep clear of it on the right (`--kv-rail-space`).
- **Orientation:** portrait and landscape (owner, M2; `UISupportedInterfaceOrientations` in `Info.plist`, no upside-down). The web build keeps its bars clear of the side insets in landscape; there the top bar, the order bar and the tab bar together cover about half of the screen.

## The native project (M2)

- **Layout:** `apps/parts-app` (`@kervan/parts-app`, private): `capacitor.config.ts`, `scripts/copy-web.mjs` (copies `apps/parts-shop/dist-app` into `www/`, gitignored, and refuses a bundle built for another origin than `VITE_SITE_ORIGIN`, default `https://kiriciparca.com`, so an app pointed at the e2e stand-in never reaches a phone), `scripts/make-icon.mjs`, `scripts/project.test.ts` and the committed `ios/` project. `ios/` was generated with `npx cap add ios` (Capacitor 8 CLI, Swift Package Manager template; it runs on Linux) and then changed only where listed here. `cap sync ios` regenerates `ios/App/App/public`, `capacitor.config.json`, `config.xml` and `ios/App/CapApp-SPM/Package.swift` (the plugin paths into `node_modules/.pnpm`); the first three are gitignored, `Package.swift` is committed and changes only with a plugin or version change.
- **Versions:** Capacitor 8 (`@capacitor/core`, `ios`, `cli` 8.6.2; `app` 8.1.2, `browser` 8.0.5, `preferences` 8.0.1), pinned exactly in `apps/parts-app` and, for the three the web code imports (`core`, `browser`, `preferences`), in `apps/parts-shop` too; `project.test.ts` fails when the two disagree. Capacitor 8 needs iOS 15+ (the deployment target) and Xcode 26+. A version bump: `pnpm add -E` in both packages, `pnpm --filter @kervan/parts-app sync`, commit `Package.swift`.
- **Config:** `appId` `com.kiriciparca.app` (permanent once on the App Store; SideStore rewrites it on the owner's phone, which is fine), `webDir` `www`, **no `server` block** (never `server.url` or `allowNavigation`: the app never loads a remote page into its web view), `ios.contentInset` `never` (the web build handles the safe areas itself), no `ios.backgroundColor` (the web view keeps the system background, white or black in dark mode, like the launch screen; `project.test.ts` checks it), `CapacitorHttp` enabled. Why: the web view's origin is `capacitor://localhost` and the site sends no CORS headers, so the app's GET requests (pages, `/kirici-modelleri.json`, 3D models) go through Capacitor's native HTTP layer via a same-origin proxy URL (`connect-src 'self'` of the CSP covers it). The site is unchanged.
- **Web side:** `src/app/native.ts` has `isNativeApp()` (`window.Capacitor.isNativePlatform()`, injected by the native layer; false in the web build, the e2e and node tests). Inside the app `openExternal` opens the site's own pages ("Sitede aç") in Safari's in-app sheet (`@capacitor/browser`) and hands every other URL to iOS; `src/app/store.ts` uses `preferencesKV()`. The plugins are dynamic imports, so the web build only carries their chunks unused. Plain links to `wa.me`, `mailto:` and `tel:` need nothing: Capacitor cancels a top-level navigation or `window.open` to an outside URL and passes it to `UIApplication.open` (WhatsApp, Mail, Phone), so no app-launcher plugin.
- **iOS project:** iPhone only (`TARGETED_DEVICE_FAMILY = 1`), iOS 15.0. `Info.plist`: `ITSAppUsesNonExemptEncryption` false (HTTPS only), `CFBundleLocalizations` tr/en, `CFBundleDevelopmentRegion` en, no camera string yet (the scanner is M4, its `NSCameraUsageDescription` comes with it). Home-screen name from `tr.lproj` / `en.lproj` `InfoPlist.strings`: **"Kervan Parça"** (TR) / **"Kervan Parts"** (EN): iOS cuts names under the icon after about 12 characters, so the full names "Kervan Kırıcı Parça" / "Kervan Breaker Parts" (19 and 20) stay for the App Store listing and the app's own title. `UIRequiresFullScreen` is not set: it only concerns iPad multitasking.
- **Privacy manifest:** `ios/App/App/PrivacyInfo.xcprivacy`: no tracking, no tracking domains, no collected data, `UserDefaults` with reason `CA92.1` (for `@capacitor/preferences`, which ships no manifest of its own). Capacitor's own frameworks ship their own (empty) manifests; nothing of theirs is repeated here.
- **Icon and launch screen:** `AppIcon-krv-1024.png`, one opaque 1024 px PNG: the shop's KRV mark (`logo-krv-v2.svg`, its own grey and ember) on white, made by `pnpm --filter @kervan/parts-app icon` (a changed icon gets a new file name). Launch screen: the system background (white, black in dark mode, as the web view behind the first page), no image and no logo (the template's Capacitor splash is removed).
- **Build (CI):** `.github/workflows/app-ios.yml` (manual "Run workflow", and PRs touching `apps/parts-app/**`, `apps/parts-shop/src/app/**`, `app.html`, `vite.app.config.ts` or the workflow): `xcode-27` runner (runner-images' Xcode 27 image, public preview) with Xcode 27.1 selected by `xcode-select`: the iOS 27.1 SDK is what lets iPhone Duo (the owner's phone, a foldable) show the app full-screen on its inner display, where an Xcode 26 build runs in a black frame, `build:app` against the live site (no DEMO catalogue, no `VITE_SITE_ORIGIN`), `check:app`, `pnpm --filter @kervan/parts-app sync`, `xcodebuild … -configuration Release -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO` (build number = the run number), then `Payload/App.app` packed as `KervanKiriciParca-<short sha>.ipa` and uploaded as it is (`actions/upload-artifact` v7.0.2, `archive: false`, no .zip around it) and kept 14 days: the artifact is the file `KervanKiriciParca-<short sha>.ipa` itself and downloads as that file. It prints counts, sizes and plist values only, has `contents: read`, no secrets, and `deploy.yml` does not depend on it. Deploy's paths filter has no `apps/parts-app/**` entry, so a change there deploys no site; a Capacitor version bump changes `pnpm-lock.yaml` (shared in that filter), which rebuilds every site preview on that PR, and `apps/parts-shop/package.json`, which rebuilds the shop's.
- **Installing on the owner's iPhone (free Apple ID):**
  1. Once: on the Windows PC install iTunes (Apple's device drivers) and iloader (64-bit, only from iloader.app or github.com/nab138/iloader); on the iPhone install LocalDevVPN from the App Store. With the iPhone on the cable and on Wi-Fi, iloader signs in with the Apple ID, installs SideStore and its pairing file. On the iPhone: Developer Mode on (Settings → Privacy & Security), the Apple ID's profile trusted (Settings → General → VPN & Device Management).
  2. Each test build: the owner uses template A7 of `docs/komut-kaliplari.md`: Claude runs `app-ios.yml` (`workflow_dispatch`) and replies with the artifact's download link and size; the download is the `.ipa` itself. Never send him clicking through the GitHub Actions pages (owner rule: browser work goes as a Cowork prompt; if he wants to fetch it himself, give him a ready-to-paste Cowork prompt that opens the latest successful "App (iPhone build)" run and downloads its `.ipa`). On the iPhone: put the `.ipa` in Files / iCloud Drive, connect LocalDevVPN, open it in SideStore (`+` on My Apps). A newer build installs over the older one (same bundle ID, so the saved machines should stay).
  3. Free accounts: an app signed this way runs for **7 days**; SideStore refreshes it (LocalDevVPN connected) before then. If SideStore itself has lapsed, run iloader on the PC again. At most **3 apps** signed by one free Apple ID at a time (SideStore is one of them) and 10 app IDs per 7 days. An iOS update or reset can invalidate the pairing file (iloader again).
- **Not verified on Linux:** the macOS build itself (Xcode, the Swift packages, signing-free packing) runs only in `app-ios.yml`; `Info.plist`, the privacy manifest and the storyboard are checked as XML/plist here, the `.pbxproj` with the CLI's own parser. Device answers (CapacitorHttp against the live site and Cloudflare, `wa.me`/`mailto`/`tel` hand-off, the in-app Safari sheet, Preferences across restarts, safe areas, the 3D viewer, the home-screen name) are for the owner's phone.

## The seams in the shop: the site output must not change

The app reaches the shop through four seams. On the site each one keeps today's behaviour, and the prerendered HTML must stay **identical apart from hashed asset file names** (proof for a change here: build the shop before and after with the DEMO catalogue and compare every HTML file with the `/assets/<name>-<hash>` names normalised).

- `src/PageView.tsx`: the page switch, split out of `App.tsx` (`App` = `Layout` + `PageView`). Also exports `showsPrice(model)`.
- `src/lib/page-source.ts`: `IS_APP`, `SITE_ORIGIN`, `PAGE_SOURCE` and `sourceUrl(path)`: where page HTML and `/kirici-modelleri.json` are fetched from (`''` on the site, `SITE_ORIGIN` in the app). Used by `palet-lines.ts` and `BreakerSearch.tsx`.
- `src/lib/asset-base.ts`: `ASSET_BASE` and `assetUrl(path)`: the prefix for media hosted on Pages (`/photos`, `/videos`, `/models`, opening frames; `''` on the site). Used by `photo-url.ts`, `tip-img.ts`, `ExplodedPicker.tsx`, `GuideVideo.tsx`, `PartViewer.tsx`. Tip and part pictures keep `VITE_TIP_IMG_BASE` when it is set.
- `src/lib/nav.ts`: `go(url)`, the one programmatic navigation (`BreakerSearch.tsx`): `location.assign` on the site, the app's router after `setNavigator()`.

The flags are read at run time with `readAppEnv(import.meta.env)`; only `VITE_APP=1` switches a seam to the app value. A new place that builds a Pages media URL or fetches a site page goes through these seams.

## Contract rule

`src/app/contract.ts` lists the page kinds the app knows (`KNOWN_KINDS`) and holds a compile-time test: a type equality between `PageModel['kind']` and that list. A kind added to or renamed in the shop (`src/lib/routes.ts`) fails `pnpm typecheck` until it is added to the list and to `PageView`. At run time an installed app that meets a kind it does not know shows UpdateNeeded instead of a broken page. Never change the shape of a page's embedded props (`kv-page`) without checking what an older app does with it.

## Rules that bite here

- The repo and CI logs are public: no prices, no price file, no catalogue in the app or its build. Prices reach the app one page at a time from the site. `build-app.mjs` and `check-app-dist.mjs` print counts only.
- Never show that parts of different models are the same: Makinelerim never merges parts lists.
- No invented numbers or references; no explanatory filler sentences on screens. Images are immutable (a changed picture gets a new file name).

## Build and test

```bash
pnpm --filter @kervan/parts-shop build:app    # dist-app/, pages from https://kiriciparca.com
pnpm --filter @kervan/parts-shop check:app    # the checks below
# against a local stand-in site (the e2e): build the shop (DEMO), then
VITE_SITE_ORIGIN=http://127.0.0.1:4173 pnpm --filter @kervan/parts-shop build:app
cd apps/parts-shop && VITE_SITE_ORIGIN=http://127.0.0.1:4173 node --experimental-strip-types --no-warnings --test e2e/app.spec.ts
```

- `scripts/check-app-dist.mjs` fails when `dist-app/` has a price-looking field with a value (JSON or JS), a tip or SKU code of the catalogue snapshot that the source does not spell out, a DEMO catalogue marker, an ads id or host of `src/lib/ads.ts` or the Cloudflare beacon, a private string (the `check-dist.mjs` list), an absolute URL to a host other than the site origin and `img.kiriciparca.com` (plus the short, commented lists of link-out hosts such as `wa.me` and of library names such as `www.w3.org` and `capacitorjs.com`, the licence banner of the Capacitor chunks; reserved `*.invalid` parsing bases do not count; run it with the same `VITE_SITE_ORIGIN` as the build), a site file (prerendered pages, `_headers`, `tips/`, `photos/` …), or passes its size or file budget (`MAX_BYTES`, `MAX_FILES`; raise them in the same PR when the app really grows, for example the bundled videos of M4).
- Unit tests run with the shop's tests (`pnpm test`; node's runner, not vitest): `src/app/*.test.ts`, the seam tests in `src/lib/`, `scripts/check-app-dist.test.ts`.
- `.github/workflows/app.yml` (PRs touching `apps/parts-shop/**` or `packages/**`): DEMO catalogue, the shop's build as the stand-in site, `build:app` and `check:app` pointed at `http://127.0.0.1:4173`, then the Playwright e2e (`e2e/app.spec.ts`, iPhone size, run with node; it serves `dist/` at the origin with CORS and clean URLs and `dist-app/` with an SPA fallback, builds `dist-app` with `build-app.mjs` when it was built for another origin, and writes the owner's screenshots when `E2E_SHOTS=<dir>` is set). CI builds the DEMO site without part prices (`SHOP_DEMO_PART_PRICES` is local only), so there the e2e gives one part item the DEMO price in the response the app reads (`editProps`); locally the real DEMO-priced page is used. It needs no secrets, has no Apple steps and never blocks a deploy. `deploy.yml` deploys `dist/` only, never `dist-app/`.
- `scripts/secret-guard.mjs` refuses Apple signing files (`*.p8`, `*.p12`, `*.mobileprovision`, `*.provisionprofile`, `*.cer`, `*.certSigningRequest`, `AuthKey_*`): signing material lives only in the GitHub environment (M3).

## Blank start guard (2026-11-15)

The first iPhone build opened on a white screen. Two guards since:

- `src/app/main.tsx` waits at most `LANG_WAIT_MS` (1.5 s, `src/app/timeout.ts`) for the stored language; a plugin call that never answers no longer keeps the app blank.
- `src/app/boot-guard.js` (emitted as `dist-app/boot-guard.js` by `vite.app.config.ts`, loaded as a plain script before the bundle, allowed by the CSP as a same-origin file) writes `bootFail` (dict) and the errors it saw on the screen when `#root` is still empty after 8 s, so a blank start on the phone can be read from a screenshot.
- WebKit can be run here for checks: download Playwright's WebKit into a scratch `PLAYWRIGHT_BROWSERS_PATH` and install its system libraries with apt; the shared Chromium is not touched.
